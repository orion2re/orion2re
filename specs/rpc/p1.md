# P1 transport foundation

Historical transport increment. The subsequent [read-sidecar increment](read_foundation.md)
adds seven implemented methods in total and replaces the original direct game/RPC
startup calls with neutral event subscriptions composed by the application.
The descriptions below of the original two-method subset are retained as scoped
transport evidence, not the current complete surface.

Prepared with AI assistance. This increment is a usable, optional WebSocket
metadata endpoint and tested bridge infrastructure, **not completion of P1**.

## Published surface

- `rpc.hello`: compare `params.key` with local `interface rpc_key`; optional
  `requestedRole` defaults to reader, optional `contractVersion` defaults to
  `orion2.rpc/0`. One controller at a time; an authenticated connection cannot
  change role in place. No generated per-launch credential or approval dialog.
- `rpc.describe`: explicit discovery of implemented methods only, optionally
  filtered by `params.methods`. The method table and argument types are generated
  from the same bundle as the schema/reference.
- All other methods return method-not-found, even when the key matches. A planned
  schema is not a handler or an authorization grant. No game state or raw native
  record is serialized by this increment.

Build/runtime are opt-in. The service binds IPv4 loopback `/rpc`, enforces
Host/local-Origin rules, rejects URL keys/binary/invalid-UTF-8 frames, reassembles
fragmented input under a total byte bound, and uses strict yyjson mode with a
bounded parsing arena, pre-parse depth guard and decoded duplicate-key rejection.
Errors use fixed messages and never echo params. A failed key closes the socket;
an empty configured key refuses listener startup.

Settings are startup-only, local, unsaved and unsynchronized. The config decoder
stores strings as CP850; the game startup hook converts the key back to UTF-8
before exact comparison. The native limit is 128 CP850 bytes, up to 384 UTF-8
bytes. Invalid-value diagnostics redact this setting instead of printing the key.

## Ownership and limits

The libwebsockets context and its foreign libuv loop live on one service thread.
The backend links the existing pinned `uv_a`, not a system or second bundled uv.
The game thread starts the listener once and, through the common
`MOX2::thunk_main2` return/exception funnel, stops/wakes/joins it before native
sound/resource/network teardown. No future input/game poll is needed to stop.
No renderer/window calls or game-rule calls occur on the service thread.

Protocol input, depth, handshake deadline, message/callback rates and output
bounds come from generated metadata. Transport output is FIFO immutable strings,
with at most 16 queued messages per connection and per-connection/global byte
caps. Writable callbacks send bounded 4 KiB WebSocket fragments; offsets advance
without rewriting a partially transmitted message. libwebsockets owns buffering
of any truncated OS write. Queue/rate overflow explicitly disconnects.

The copied-work bridge additionally bounds 64 outstanding tickets globally,
16 per registered client, 1 MiB per completion and 4 MiB of ready completions.
It copies inputs/results, rejects duplicate/late completions, expires unstarted
work from service housekeeping, and invalidates all work/results on epoch/client
revocation. Overflow revokes that client so the service disconnects rather than
silently losing a result. These finite bounds are not a measured maximum-game
capture/output budget; gameplay payload sizes may require revisiting them.

Native query pumps and perspective-reset hooks are deliberately not wired yet.
Future adapters must use one consistent monotonic millisecond timebase for queue
deadlines and dispatch, and must capture only approved projections on the game
thread. Bridge mechanics alone are not player authorization or a coherent world
snapshot. There is no subscription/state coalescing implementation yet.

## Verified checks and reproduction

Native checks performed on macOS ARM64 / AppleClang 17:

```sh
# Existing default build (RPC off):
bash tools/run-tests.sh

# With the pinned backend checkout and an RPC-enabled test build:
cmake --build out/build/rpc-debug --target orion2re test_rpc --parallel 4
ctest --test-dir out/build/rpc-debug -R '^test_rpc' --output-on-failure

# Standalone live tests, using only Python's standard library:
ORION2RE_RPC_TEST_SERVER=out/build/rpc-debug/rpc-test-server \
  python3 -m unittest discover -s tests/rpc -p test_transport.py -v

# Canonical outputs:
python3 tools/generate_rpc_schema.py --check
python3 tools/audit_rpc_contract.py
```

The existing 105 CTest targets pass with RPC off, including local config binding,
CP850 key round-trip and save/synchronization exclusion checks. The optional game
executable links successfully with RPC on. The C++ RPC target tests strict
envelopes/arguments, key matching, correlation/redacted errors, queue capacity,
owned copies, expiry, revocation, duplicate/late completion, cross-thread handoff,
startup/bind failure and stop without a game poll.
The RPC C++ and live transport targets also pass with AddressSanitizer and
UndefinedBehaviorSanitizer enabled on the local native build.
The C++ target covers 12 cases; the Python contract/schema/live
suite reports 61 passing tests (19 live transport cases). Generator drift checks,
C++ formatting and new-file whitespace checks pass. A fresh router-only build
also succeeds with RPC requested and an intentionally nonexistent backend path;
its link command contains neither RPC nor libwebsockets.

The live harness tests actual masked WebSocket frames, split TCP headers,
fragmented/coalesced requests, wrong/absent credentials, discovery filtering,
single-controller ownership, HTTP Host/Origin/path checks, binary/oversize/UTF-8
rejection, duplicate keys, auth deadline, connection/request floods, a 32 KiB
fragmented publication, revocation/bridge overflow, and shutdown with an unread
512 KiB synthetic publication. The fixture key and stdin publication commands
belong only to `rpc-test-server` (excluded from the default build/package), not
the game or its wire method catalog.

Two integration constraints were verified against this exact backend revision:

1. Final foreign-loop context destruction requires a final destroy call after
   close callbacks; `pcontext` then becomes null. Merely assuming the first
   destroy call freed everything is incorrect.
2. An async lws timeout inserted from an independent foreign-libuv timer does
   not necessarily wake lws' own timer. Authentication expiry/revocation use the
   synchronous-close API from our own timer, where no wsi callback is being
   serviced. Tests reproduce and guard against deferred idle-socket revocation.

CI defines native Linux x64/x86, macOS, MSVC x86/x64 and POSIX MinGW x86/x64
build checks; cross-built MinGW binaries are build-checked, not executed on Linux.
Those CI results are **not claimed to have run locally**.

## P0 gate assessment

- **P0-06 stays open.** Backend selection, pin, notices, project-uv integration,
  native build and actual local transport/lifecycle tests are now exercised.
  Missing non-local target results must be obtained from the matrix before
  claiming supported-platform approval.
- **P0-09 stays open.** Message/queue/output limits are now enforced, and synthetic
  output exercises fragmentation/backpressure. No native maximum-game projection
  exists yet; transport tests cannot substitute for its capture size/cost.
- **P0-10 stays open.** Default unit/save/config tests pass, but native interactive
  traces and whole-game save/mod/RNG comparisons still require local legitimate
  game assets and fixtures. No proprietary assets or saves were added.

Next implementation work is a game-thread query pump with explicit committed/busy
boundaries, game/perspective identity and reset hooks, followed by the initial
audited player projections. Gameplay methods must not be added to
`implementedMethods` until those paths and their visibility tests exist.
