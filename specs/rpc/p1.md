# Transport ownership and backend constraints

AI-assisted current implementation notes. Build/authentication/protocol details
and shared checks are in [README.md](README.md); capture semantics are in
[read_foundation.md](read_foundation.md). The canonical registry defines enabled
methods. A schema alone does not enable a handler.

The libwebsockets context and foreign libuv loop belong to one service thread,
using project `uv_a`. Renderer/native game operations stay off that thread.
Shutdown cancels/wakes/joins independently of another game poll and precedes
native resource teardown.

Output owns immutable strings, enforces per-client/global message/byte limits,
and sends bounded 4 KiB fragments. Offsets advance without rewriting started
messages; libwebsockets owns truncated OS-write buffering. Queue/rate overflow
disconnects explicitly. The copied bridge bounds admission/completion, deadlines,
client/epoch revocation and late results; it grants no gameplay authority.
Current numeric limits are canonical in `contracts.json` and generated metadata.

Two constraints are specific to the pinned backend and must survive refactoring:

1. Foreign-loop context shutdown requires a final destroy call after close
   callbacks; do not assume the first destroy freed everything.
2. An async lws timeout inserted from an independent foreign-libuv timer may not
   wake lws' timer. Housekeeping uses synchronous close outside wsi callbacks for
   authentication expiry/revocation; tests guard idle-socket closure.

`rpc-test-server` is a non-packaged synthetic harness, not an extra game API.
Live tests exercise masked/fragmented/coalesced frames, strict JSON/UTF-8, upgrade
policy, authentication/controller ownership, floods, backpressure, revocation and
shutdown. Native macOS ARM64 transport and sanitizer results do not establish
the remaining cross-platform or interactive acceptance gates; see [evidence.md](evidence.md).
